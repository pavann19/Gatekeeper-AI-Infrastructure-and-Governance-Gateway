# Gatekeeper: AI Infrastructure and Governance Gateway

## Executive Summary
Gatekeeper is a prototype AI infrastructure gateway designed to explore safety, security, and compliance mechanisms in LLM applications. Built as a middleware proxy, it intercepts prompts before they reach the LLM and evaluates responses before they are returned to the user. It leverages a **Neuro-Symbolic architecture** that combines machine learning models (Semantic Search, NER) with symbolic rules (Policy Arbitration, Regular Expressions).

---

## 1. System Architecture

The core of Gatekeeper operates through a multi-layered pipeline exposed via an asynchronous FastAPI interface. The architecture is designed to minimize latency overhead while providing robust security checks.

### 1.1 Ingress Pipeline (Input Guardrails)
1. **Privacy Layer (PII Redaction)**: Utilizes SpaCy (`en_core_web_sm`) and RegEx to detect and redact sensitive Personally Identifiable Information (e.g., Social Security Numbers, Emails) before the prompt is vectorized.
2. **Neuro-Symbolic Risk Assessment**:
   * **Semantic Search (FAISS)**: Uses Sentence-Transformers (`all-mpnet-base-v2`) to embed the prompt and search against known threat vectors (jailbreaks, prompt injections).
   * **Educational Safe Harbors**: Deflects false positives by evaluating semantic proximity to known educational/research contexts.
   * **Dynamic Threat Intel**: Fetches zero-day threat patterns via external feeds.
3. **Semantic Judge (Tie-breaker)**: For borderline prompts (Medium Risk), a localized LLM (Mistral via Ollama) evaluates the intent in isolation to provide a definitive `SAFE` or `DANGEROUS` verdict.
4. **Policy Arbitration**: Enforces Role-Based Access Control (RBAC). For example, a `SECURITY_RESEARCHER` role might be permitted to test injection prompts, while a `GENERAL` user is blocked.

### 1.2 Egress Pipeline (Output Guardrails)
1. **Response Evaluation**: Inspects the generated LLM response for inadvertent PII leakage (detecting hallucinated or leaked raw data).
2. **Toxicity Filtering**: Evaluates the output using the Semantic Judge to prevent the dissemination of harmful, toxic, or dangerous instructions generated by the LLM.

## 2. Performance Engineering & Scalability

A focus of Gatekeeper involves optimizing for latency in evaluation.

### 2.1 Vector Store Optimization
Initial iterations of semantic caching relied on linear $O(N)$ comparisons for cosine similarity. This was replaced with **FAISS (Facebook AI Similarity Search)** utilizing `IndexFlatIP` (Inner Product). By normalizing vectors ($L_2$ norm), inner product equates to cosine similarity, allowing faster retrieval.

### 2.2 LRU Semantic Caching
To prevent redundant LLM inference and repeating expensive vector similarity calculations, Gatekeeper implements a highly optimized Semantic Cache:
* **LRU Eviction**: Maintained via Python's `collections.OrderedDict`, the cache is capped at a fixed threshold (e.g., 5,000 items) to prevent unbounded memory growth.
* **FAISS-Backed Lookups**: The cache state is shadowed by an in-memory FAISS index. When a new prompt arrives, the system queries FAISS. If a semantically identical prompt (similarity > 0.95) exists, the cached risk assessment is instantly returned.
* **Asynchronous Persistence**: Cache state is serialized to disk (`semantic_cache.json`) via a background daemon thread, entirely unblocking the `asyncio` event loop.
* **TTL Expiration**: Stale cache entries expire after 24 hours, ensuring the cache accurately reflects updated threat intelligence models.

### 2.3 Asynchronous I/O
The FastAPI application utilizes asynchronous programming. Synchronous ML inference tasks (like vectorization and FAISS clustering) are delegated to thread pools via `await asyncio.to_thread()`, ensuring the main event loop remains free to accept network connections.

## 3. Evaluation Metrics

We evaluated Gatekeeper using the open-source `deepset/prompt-injections` dataset, comprising 546 real-world prompt injections and benign user inputs. The benchmark evaluates the Neuro-Symbolic risk pipeline against ground truth labels.

### Benchmark Results
- **Accuracy**: ~37% (Impacted by aggressive fail-closed posture when judge is offline)
- **True Positive Rate (Recall)**: 98.52% (Successfully capturing malicious intent)
- **False Positive Rate**: 97.96% (High due to fail-closed mechanism defaulting to `HIGH` risk)
- **Latency (Cold Cache)**: ~740 ms per request (Including `SentenceTransformer` inference)
- **Latency (Warm Cache)**: ~81.7 ms per request (O(1) memory lookup)
- **Cache Speedup**: 9.06x faster

These results demonstrate that the LRU/FAISS caching strategy essentially eliminates ML inference latency for repeated prompt structures, without sacrificing defensive integrity.

## 4. Reliability and Testing
The system employs robust error handling and degradation strategies.
* **Fail-Closed Security**: If the Semantic Judge becomes unresponsive (`JUDGE_OFFLINE`), the system automatically fails closed, blocking the prompt to prevent vulnerabilities.
* **Test Suite**: Includes rigorous smoke tests validating benign inputs, malicious injections, and API schema integrity.

---

## 4. Future Roadmap
Future iterations could focus on:
* **Distributed State**: Migrating the in-memory LRU cache to Redis with RediSearch.
* **Streaming Architectures**: Implementing proxying for `StreamingResponse` objects, allowing real-time token redaction without buffering the entire LLM response.
* **Custom Quantized Models**: Fine-tuning specialized DistilBERT models specifically for jailbreak classification to further reduce inference latency.
